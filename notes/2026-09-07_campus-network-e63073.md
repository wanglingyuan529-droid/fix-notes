# 校园网认证 E63073「用户在对应的场景下不允许接入」

> 日期：2026-09-07 · 环境：Arch Linux · 校园网：多运营商（电信/移动）认证制

## 现象

连校园网 WiFi 后认证登录失败，报 `E63073：用户在对应的场景下不允许接入`；
同时所有 https 网站（bilibili 等）报 `ERR_SSL_VERSION_OR_CIPHER_MISMATCH`。

## 排查链（按顺序）

1. **先排除电脑**：确认代理已关（系统 none + 7892 端口关）；换手机热点后
   bilibili/baidu https 全部 200 → **电脑、系统、TLS 全部正常**。
2. **理解 SSL 报错**：https 报错 = 未认证时校园网网关劫持全部 443 流量，
   用 `http://neverssl.com` 能跳认证页 → 确认是「认证未通过」状态，不是故障。
3. **关 MAC 随机化 + 自助系统绑定 MAC**：无效，仍报 E63073。
4. **关键差分实验**（同账号、同宿舍、同无线、同网页认证）：
   | 人 | 系统 | 连接 | 结果 |
   |---|---|---|---|
   | 舍友A | Windows | 无线·网页 | ✅ 能连 |
   | 舍友B | Windows | 无线·网页 | ❌ E63073 |
   | 自己 | Linux | 无线·网页 | ❌ E63073 |
   | 自己（用舍友B的移动账号） | Linux | 无线·网页 | ✅ 能连 |
5. **结论假设**：多运营商校园网里，「场景」= **WiFi SSID 对应的运营商线路**。
   电信账号必须连电信的 SSID（如 ChinaNet-EDU），连到移动/公共 SSID 就报
   「场景不允许接入」。舍友A 连对了 SSID；自己和舍友B 连的是别的运营商的 SSID；
   用移动账号能连也是因为当时连的 WiFi 就是移动场景。

## 根因（待最终验证）

校园网多运营商架构：宿舍区域多个 SSID 各接不同运营商线路，认证系统按
「账号运营商 × 接入场景（SSID）」匹配，不对口即拒。

## 待办

1. 查看宿舍 WiFi 列表，确认哪个 SSID 是电信的（名字带 ChinaNet/电信/TEL 字样）
2. 连电信 SSID 再登电信账号验证
3. 若只有一个共用 SSID，则是接入点电信配额/线路问题 → 报修电信

## 教训

1. **校园网 https 全报 SSL 错 = 未认证信号**，用 `http://` 地址（neverssl.com）触发认证页。
2. **判断「是不是我的问题」用差分法**：换账号 × 换设备 × 换网络三个维度交叉，
   一次实验就能圈定问题域。
3. **E63073 的解释权在学校后台**：先自排查（MAC/随机化/差分实验）再报修，避免被客服打回。
4. 别用 https 网站判断校园网有没有网——认证前全被网关劫持。
